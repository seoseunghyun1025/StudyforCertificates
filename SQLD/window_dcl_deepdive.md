# 📑 SQLD 마스터를 위한 오늘자 심화 학습 정리 노트

## 1. ROLLUP & CUBE: 중첩 괄호 `(())`와 결합 컬럼
단순한 문법 차이가 아니라 **'집계의 계층'**을 어떻게 제어하느냐가 핵심입니다.

### 🔹 결합 컬럼 (Composite Column)의 원리
- **개념:** `(A, B)`처럼 괄호로 한 번 더 묶으면 SQL 엔진은 이를 쪼개지지 않는 **'하나의 단위'**로 인식합니다.
- **작동 방식:** 일반적인 `ROLLUP`은 오른쪽 컬럼부터 하나씩 빼면서 소계를 내지만, 결합 컬럼은 덩어리째 빠지기 때문에 **A만 따로 집계하는 중간 단계가 사라집니다.**

### 🔹 문법별 집계 조합 (Grouping Sets) 상세 비교
| 문법 | 생성되는 집계 조합 (결과 행의 종류) | 특징 |
| :--- | :--- | :--- |
| `ROLLUP(A, B)` | `(A, B)`, `(A)`, `()` | A별 소계가 포함됨 |
| `ROLLUP((A, B))` | `(A, B)`, `()` | **A별 소계 생략** (상세 + 전체 합계만 출력) |
| `ROLLUP((A, B), C)` | `(A, B, C)`, `(A, B)`, `()` | (A+B) 묶음 소계는 나오지만, A 단독 소계는 없음 |
| `CUBE((A, B), C)` | `(A, B, C)`, `(A, B)`, `(C)`, `()` | (A+B) 소계와 더불어 **C(연도 등) 단독 소계**까지 출력 |

## 2. 윈도우 함수 (Window Function) 핵심 3원칙
원본 데이터를 유지하면서 집계 기능을 수행하는 윈도우 함수의 작동 메커니즘입니다.

### ① PARTITION BY와 GROUP BY의 유사성 및 차이점
- **유사점:** 데이터를 특정 기준(부서, 직급 등)으로 '끼리끼리' 그룹화합니다.
- **차이점:** `GROUP BY`는 행을 합쳐서 결과를 줄이지만, `PARTITION BY`는 **원본 행의 수를 그대로 유지**하며 옆에 계산 결과만 덧붙입니다.

### ② PARTITION BY 생략 시의 동작 (`OVER()`의 비밀)
- `OVER()` 내부가 비어있다면, SQL은 테이블 **전체 데이터를 하나의 파티션**으로 봅니다.
- 피자를 조각내지 않고 통째로 서빙하는 것과 같으며, 전체 총합이나 평균이 모든 행에 동일하게 출력됩니다.

### ③ 파티션의 논리적 경계 (Boundary)
- 파티션은 데이터 간의 **'투명한 벽'**입니다. 윈도우 함수는 이 벽 안의 데이터만 참조합니다.
- 예: '영업부' 파티션에서 매긴 순위는 '인사부' 데이터가 몇 점이든 상관없이 영업부 안에서만 결정됩니다.

## 3. 행 간 이동 함수: LAG & LEAD 상세 분석
데이터의 전후 관계를 파악할 때 필수적인 함수입니다.

### 🔹 LAG (지연 - 과거 데이터 참조)
- **문법:** `LAG(컬럼, 오프셋, 기본값)`
- **오프셋 활용:** `LAG(sal, 2)`는 내 위로 두 번째 사람의 값을 가져옵니다.
- **실전 케이스:** 직업(job)별로 나눈 파티션에서 1, 2번 사원은 자기보다 2칸 앞선 데이터가 없으므로 `NULL`이 나옵니다.

### 🔹 LEAD (리드 - 미래 데이터 참조)
- **개념:** 현재 행을 기준으로 **다음 행**의 값을 미리 가져옵니다.
- **용도:** 현재 작업 시간과 다음 작업 시작 시간 사이의 간격을 계산하는 등 '미래 시점' 비교에 사용합니다.

## 4. DCL (Data Control Language): 권한 제어와 보안
데이터베이스 접근 권한을 관리하며, 시험에서 함정 문제가 많이 출제되는 영역입니다.

### 🔹 GRANT & REVOKE의 기본 원칙
- **준 사람이 뺏는다 (Grantor Rule):** 특정 사용자에게 권한을 준 **허가자(Grantor)**만이 해당 권한을 취소할 수 있습니다. (관리자 DBA는 예외적으로 상시 가능)

### 🔹 CASCADE (연쇄 취소)의 함정
1. **상황:** Lee가 Kim에게 권한을 주고(With Grant Option), Kim이 다시 Park에게 권한을 준 상태.
2. **현상:** Lee가 Kim의 권한을 `REVOKE`할 때 `CASCADE` 옵션을 쓰지 않으면, **Kim의 권한만 취소되고 Park의 권한은 그대로 남을 수 있습니다.** (이미지 실습 사례)
3. **해결:** 줄줄이 사탕처럼 모두 회수하려면 반드시 **`CASCADE`** 옵션을 명시해야 합니다.

### 🔹 GRANT 옵션 비교
- **`WITH GRANT OPTION`**: 객체 권한용. 취소 시 CASCADE가 적용되어 연쇄 취소됩니다.
- **`WITH ADMIN OPTION`**: 시스템 권한/롤용. 취소 시 해당 사용자만 취소되며 연쇄 취소되지 않습니다.

## 5. 이미지 실습 문제 및 결과 해석

### 📌 [추천내역 테이블] ROW_NUMBER 결과
- 쿼리: `ROW_NUMBER() OVER(PARTITION BY 추천경로 ORDER BY 추천점수 DESC)`
- 결과: SNS, 홈페이지 등 각 경로별로 최고 점수부터 1, 2, 3번이 매겨집니다.
- 포인트: **방(Partition)이 바뀔 때마다 번호는 다시 1번부터 시작**한다는 것을 확인했습니다.

### 📌 [사원 테이블] LAG(sal, 2) 결과
- 매니저 방에서 'blake(1번)', 'clark(2번)'은 위에 두 명이 없으므로 `NULL`이 나옵니다.
- 3번인 'jones'부터 비로소 1번 'blake'의 점수인 `2850`을 가져와 옆에 찍어줍니다.
