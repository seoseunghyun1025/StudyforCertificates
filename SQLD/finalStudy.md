# 📊 SQL 및 데이터 모델링 핵심 요약 (2026-03-06)

## 1. Top-N 쿼리와 실행 순서의 비밀
### 🔹 SQL Server: `TOP(n) WITH TIES`
- **의미**: "상위 n개를 가져오되, n등과 성적이 같은 공동 순위가 있다면 걔네도 다 데려와라."
- **필수 조건**: 반드시 `ORDER BY`가 있어야 순위를 매길 수 있음.

### 🔹 Oracle: `ROWNUM`의 함정
- **실행 순서**: `FROM` → `WHERE` → `SELECT` → `ORDER BY`
- **주의점**: `WHERE ROWNUM <= 3`은 정렬하기 전에 눈에 보이는 3개를 먼저 뽑는 것임. 제대로 하려면 서브쿼리로 먼저 정렬한 뒤에 `ROWNUM`을 매겨야 함.
- **`ROWNUM = 3`이 안 되는 이유**: 1번 행이 조건을 통과해야 2번 번호가 생김. 1번을 건너뛰고 3번만 뽑는 건 불가능.

## 2. 집계 함수와 그룹화 (`GROUP BY`, `HAVING`)
- **`COUNT(*)`**: NULL을 포함한 전체 행 수.
- **`COUNT(컬럼)`**: NULL은 빼고 개수를 셈.
- **`GROUP BY`**: 테이블을 특정 기준(학과 등)으로 '바구니'에 나눠 담는 것. 결과 건수는 바구니의 개수임.
- **`HAVING`**: 만들어진 바구니들에 필터를 거는 것. (예: 인원이 2명보다 많은 학과만!)

---

## 3. 데이터 모델링 (ERD 읽는 법)
### 🔹 식별 vs 비식별 관계
- **식별 (실선)**: 부모의 PK가 내 PK가 됨. 부모 없인 못 삼.
- **비식별 (점선)**: 부모의 PK가 내 일반 속성(FK)이 됨. 부모랑은 별개로 나만의 ID가 있음.

### 🔹 필수 vs 선택 관계
- **막대기 (|)**: Mandatory. "너 나 없으면 안 돼(필수)."
- **동그라미 (o)**: Optional. "나 없어도 상관없어(선택)."

---

## 4. 정규화와 무결성
- **제2정규화 (2NF)**: 기본키가 복합키(A+B)일 때, A나 B 하나에만 종속되는 속성이 있다면 테이블을 쪼개야 함 (부분 함수 종속 제거).
- **Unique Key**: 중복은 안 되지만 NULL은 들어갈 수 있음. (Oracle은 여러 개 가능, MSSQL은 딱 하나만 가능)
- **도메인 (Domain)**: 컬럼 하나가 가질 수 있는 값의 범위(타입 + 크기 + 제약조건).

---

## 5. 집합 연산과 형변환
- **`UNION ALL`**: 중복 상관없이 다 합침. 정렬 안 해서 빠름 (실무 권장).
- **`UNION`**: 중복 제거함. 내부적으로 정렬하느라 느림.
- **형변환**: `TO_CHAR`(문자로), `TO_DATE`(날짜로), `TO_NUMBER`(숫자로).
- **이유**: 데이터 타입을 맞춰야 계산이 되고, 인덱스 성능 저하(암시적 형변환)를 막을 수 있음.

---

## 6. 윈도우 함수
- **`FIRST_VALUE`**: 그룹 내에서 정렬했을 때 가장 첫 번째 나오는 값을 가져옴.
- **`LAG / LEAD`**: 이전 행이나 다음 행의 값을 가져올 때 사용.
